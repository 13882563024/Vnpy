# 跨期均值回归策略 · 使用说明

> 实现方案：`docs/plan/PLAN-spreadtrading-跨期均值回归策略实现.md`
> 策略规格来源：`docs/SDR/cross_period_strategy_recommendations.md`

## 1. 快速开始

```powershell
# 1) 离线自检：不连柜台，只校验注册表、策略类、参数
.venv\Scripts\python.exe run_strategy.py --list

# 2) 单元测试（标准库 unittest，不需要 pytest）
.venv\Scripts\python.exe -m unittest discover -s tests -t .

# 3) 采集行情（只连行情前置，不碰交易端）
.venv\Scripts\python.exe run_recorder.py --minutes 110

# 4) 只计算不发单（连柜台取行情，日志打印每层止盈目标价）
.venv\Scripts\python.exe run_strategy.py --spread A_2611_2701

# 5) 真实报单
.venv\Scripts\python.exe run_strategy.py --spread A_2611_2701 --live
```

连接参数复用 `~/.vntrader/ctp_connect.json`（GUI「交易 → 连接 CTP」保存后生成），字段清单见
README 第 5.1 节。

**默认不发单**：策略的 `live_trading` 默认 `False`，此时只计算并打印信号与每层止盈目标价。
这一档是给实盘前核对用的（方案 T8）。

> ⚠️ **真实带钱账号请注意三个入口的连接范围差异**
>
> | 入口 | 连接范围 | 会不会报单 |
> | --- | --- | --- |
> | `run_recorder.py`（采集） | **只连行情前置**，进程内没有交易 API | 不可能 |
> | `run_backtest.py`（回测） | 不连柜台，只读数据库 | 不会 |
> | `run_strategy.py`（策略） | 连**交易前置**（认证/登录/查合约与持仓）+ 行情前置 | 仅 `--live` 时会 |
> | GUI `main.py` | 连交易前置 + 行情前置（同 `run_strategy.py`） | 仅策略里 `live_trading=True` 时会 |
>
> 只想采数据、不想让交易端登录，就只用 `run_recorder.py` + `run_backtest.py`。

### 1.1 GUI 操作路径（`run.bat` / `python main.py`）

> **现行 GUI（2026-11-02 更新）**：菜单「功能 → 价差交易」现在打开本项目的跨期合约管理窗口，而不是下面旧版 vn.py 原生创建价差表单。以下旧版步骤保留作历史参考，实际按本节新流程操作。**仅 DCE.SP 格式新合约开放单字段添加**；没有真实柜台合约和实时有效两腿行情时无法开启交易。
>
> 1. 连接 CTP；「功能 → 价差交易 → 添加合约」，输入 `DCE.SP a2701&a2703`。系统自动建立 near/far、合成报价和两腿 tick 录制；无需填写腿、公式或 JSON。可多次添加其他合约，左侧切换详情。
> 2. 在所选合约的「查看与编辑策略参数」可配置：**N 均值窗口（分钟）、M 标准差窗口（分钟）、X 开仓阈值（sd）、层距（sd/层）、最多层数、每层手数、整仓止损、每手保证金、盘口宽度上限（tick）、最小深度、量比上限、中文备注、只平仓、预挂止盈、最大持仓日、净止盈金额、平仓单超时、开仓部分成交超时、自定义手续费**；合约乘数与最小变动由柜台单腿合约自动验证后填入，界面只读，避免用组合合约的 `VolumeMultiple=0` 算错金额。修改 N/M 会重置统计窗口，需重新积累行情；保存后建议重新核对一次柜台。随后点顶部「核对柜台状态」：程序会向柜台发起**资金/持仓查询**，并**一次性验证所有已管理合约**的乘数/最小变动/组合合约是否挂牌；核对结果列出每个合约的委托/持仓/策略层明细。**核对本身不会因为已有持仓或委托而失败**——持仓、在途委托只是账户的真实状态，不是核对错误。确认后所有合约都标记为已核对；真正开启某个合约时，`validate()` 会**只拦截该合约自身**的在途委托、单腿持仓、引擎净仓和策略层账，OI 等有历史持仓的合约不会阻止另一个干净合约交易。账户数据未返回时会明确警告并记为“人工确认”，不会直接阻断，但您必须已在主终端核对过资金和持仓。程序展示的是已查询到的状态，不能证明柜台查询全部完成，请再与主终端的委托/成交记录核对。确认后开启该合约「允许此合约交易」，最后点「开始交易」复核合约并确认实盘。总开关和每项开关默认关闭；组合合约未在柜台查询到、缺两腿实时报价、交易端未就绪、已有在途单或持仓未核对时拒绝启动。不把组合单隐式改为两腿执行。
> 2.1 **只平仓/超时说明**：勾选「只平仓」后忽略所有开仓/加仓信号；「预挂止盈」表示开/加仓成交后立即挂止盈单。`平仓单超时=0` 表示止损/换月平仓单不成交也不撤单重发（可能一直挂着，需人工处理）；`开仓部分成交超时=0` 表示部分成交后不撤剩余。两者都为 0 时，策略自身不会因超时撤单；但这不等于保本或保成交。
>
> 2.2 **手续费**：在「手续费（影响预挂止盈价）」里勾选“自定义手续费”，填**每手每边**的开仓/平昨/平今费用；单位 `元` 表示元/手/边，`万分之` 表示按成交金额比例（价格×乘数×手数×费率÷10000）。不勾选则按 `fees/fee_table.json` 的品种费率（A 当前为 2/2/2 元）；该表由 `tools/build_fee_table.py` 从 `docs/全品种手续费表_交易所标准_20260919(1).xlsx` 生成，**只有交易所标准，不含期货公司加收**，实际账户费率不同时请用自定义手续费。预挂止盈目标价会加回该层“开+平”四条腿费用，因此手续费填错会直接导致目标价偏离。
>
> 2.2.1 **全局资金占用上限**：点顶部「全局风控」，可设置“已用资金达到 X% 后不再开仓/加仓”（默认 70%）。口径为 `(权益 − 可用资金) ÷ 权益`，包含占用保证金与冻结资金；达到阈值只拦截开仓/加仓，平仓、止盈、止损不受影响。没有账户资金数据时会拒绝开仓（fail-closed）。配置写入 `config/risk.json`，修改后下一次开仓决策即生效，不需要重启。
>
> 2.3 **旧持仓接管**：如果启动时发现价差有净仓、但策略层账为空（例如旧版本按单腿回报未建层），启动会尝试按两腿仓位数量和柜台/持久化的持仓均价接管成第 1 层，标记为“接管旧持仓”，并补挂止盈；两腿数量不一致或缺均价时会拒绝启动。接管不是自动平仓，也不会反向开仓，仍需人工核对。
>
> 3. 点「停止交易」**只暂停策略，不撤销已有委托、不自动平仓**；旧委托仍可成交，已有持仓也不再受策略自动止损保护，界面继续显示行情/委托。关闭窗口或断开连接同样暂停并要求重新核对。再次启动前必须核对柜台订单、成交和单腿仓位；有在途算法、委托或未核对仓位时会拒绝自动恢复，须人工处置。需要主动撤单或平仓时使用主终端手工交易功能，不能将停止交易当作撤单按钮。
> 4. 新增合约会保存到 `config/spreads.json`；仅增加交易所组合代码这一项输入。当前 GUI 只放行经验证的交易所组合单执行，旧版两腿执行及其他交易所格式仍需后续专门适配。历史数据在「功能 → 行情数据」查看。GUI 进程会继续采集两腿 tick，但采集是否成功取决于行情连接及实际交易时段。
> 5. **删除合约**：先在所选合约上点「删除合约」。删除会移除策略实例、价差注册和 `config/spreads.json` 条目，**不删除已采集的历史 tick**。存在在途委托、未终结委托、价差/单腿持仓或策略层账时会拒绝；交易端已连接时还要求先完成柜台核对。总交易运行中不能删除，必须先「停止交易」。交易端未连接时程序无法核对持仓，只有在您已确认账户无该组合持仓时才应继续（离线删除）。
> 6. **交易日志与报单依据**：每笔真实报单前会打印一行 `报单依据[...]`，包含层号/方向、价差 mid/bid/ask、mean/sd、z 值、开仓阈值、盘口宽度、最小深度、报单量价、每层止损、每手/本单保证金、执行方式（two_leg/exchange_spread）、组合代码与策略名；算法侧再打印 `报单已提交 ...`（委托号、合约、方向/开平、量价、用途、模式、算法号、策略名、依据）。委托状态变化打印 `委托状态 ...`，成交由模板打印 `委托成交[...]`；暂停期间的成交额外标记为「暂停期间成交…仅被动记账」。被过滤器拦截的开仓按原因限频打印 `开仓被过滤`。核对完成时还会写一条 `柜台核对完成：...当前敞口：...` 日志。日志同时写入 `~/.vntrader/log/vt_YYYYMMDD.log` 和主窗口「日志」面板。

以下为**旧版原生价差面板操作（不再适用于当前入口）**，仅留作旧配置对照：

启动后会在日志里打印一条 **「跨期策略接线完成：策略类 N 个（含 CrossPeriodMRStrategy），
算法类 CrossPeriodAlgo（maker 挂单，不会立即吃单），价差 新建 x / 已存在 y」** ——
看到它说明下面三件事已经就绪：

1. 策略类已加载（价差面板的策略类下拉里能选到 `CrossPeriodMRStrategy`）；
2. 算法类已换成 `CrossPeriodAlgo`（**不会**退回 `SpreadTakerAlgo` 立即吃单）；
3. `config/spreads.json` 里的价差已注册（价差面板里直接能看到）。

然后按顺序操作：

| 步骤 | 位置 | 说明 |
| --- | --- | --- |
| ① 连接柜台 | 菜单 **交易 → 连接 CTP** | 配置已保存在 `ctp_connect.json`，直接点「连接」即可（会同时登录交易端与行情端） |
| ② 看价差 | 应用 **价差交易** → 「价差」页 | 应能看到 `A_2611_2701` / `OI_701_703` / `RM_701_703` / `J_2611_2701` 及其买卖价差 |
| ③ 添加策略 | 「策略」页 → 选策略类 → **添加策略** | 弹窗里填：`strategy_name`（自定义，如 `OI_701_703_MR`）、`spread_name`（下拉/填价差名）；其余参数保持默认，**`live_trading` 留 False** |
| ④ 初始化 → 启动 | 选中策略 → **初始化** → **启动** | 初始化会加载费率、算乘数/最小变动并打印自检日志 |
| ⑤ 看输出 | 同页「日志」区 | `live_trading=False` 时只会打印开仓信号与每层止盈目标价，**不会报单** |

确认信号与目标价都正确后，若要真实报单：选中策略 →「编辑」→ 把 `live_trading` 改成 `True`
→ 停止后重新启动。**改之前请先在纸上核一遍 `stop_loss` / `max_positions` / `layer_volume`。**

> GUI **不做**两件事，需要用命令行：
> - **采集 tick**：vnpy 没有内置落库组件（未装数据管理应用）→ `run_recorder.py`
> - **价差回测**：「CTA 回测」是单合约 bar 级回测，不认价差 → `run_backtest.py`

## 2. `config/spreads.json`：合约对注册表

程序**不自动选合约、不拼接组合代码**，两者都由用户维护。每个价差一个条目：

```json
"A_2611_2701": {
  "legs": ["a2611.DCE", "a2701.DCE"],
  "active_symbol": "a2611.DCE",
  "exchange_spread": "SP a2611&a2701",
  "exchange": "DCE",
  "product": "A",
  "remark": "a 1-3 正套，重点观察",
  "margin_per_lot": 5000,
  "size": 10,
  "pricetick": 1,
  "vr_max": 0,
  "executor": "two_leg",
  "stop_loss": 10000,
  "trading_sessions": "night_2300",
  "slug": "",
  "strategy": {
    "max_positions": 3,
    "max_hold_days": 999
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `legs` | **两腿**，第一腿 = `near`、第二腿 = `far`，`spread = near − far` |
| `active_symbol` | 两腿执行器里的**主动腿**（默认 `legs[0]`），必须是 `legs` 之一 |
| `exchange_spread` | 交易所挂牌组合代码**原始字符串**（含空格与 `&`，程序不 trim、不拼接） |
| `exchange` | 组合合约所在交易所，用于把 `exchange_spread` 拼成 vt_symbol（若 `exchange_spread` 自带 `.DCE` 后缀则不拼） |
| `remark` | 中文备注（≤120 字），只用于界面和日志展示 |
| `margin_per_lot` | 每手保证金（元），由用户填写；`0` = 未填写。只用于展示/日志，不参与报单校验 |
| `fee` | 可选自定义手续费：`{"unit":"元|万分之","open":...,"close_yesterday":...,"close_today":...}`；空对象 = 用 `fees/fee_table.json`。直接影响预挂止盈目标价与净利计算 |
| `trading_enabled` | GUI「允许此合约交易」的持久化标记；重启后恢复为允许，但仍需核对柜台并手动「开始交易」，不会自动启动 |
| `size` / `pricetick` | **单腿合约**乘数与最小变动价位；组合合约 `VolumeMultiple=0`，不能用它。GUI 添加的合约由柜台验证自动写入，不在界面手改 |
| `vr_max` | 成交量比例过滤，`0` = 不启用；RM 建议 `10`，其余 `0` |
| `executor` | `two_leg`（默认）或 `exchange_spread` |
| `stop_loss` | 整仓止损金额（元），按层摊：每层上限 = `stop_loss ÷ max_positions` |
| `trading_sessions` | `day_only` / `night_2300` / `night_0100` / `night_0230` / `index_futures` / `always` / 空=不限，或显式 `day:09:00-10:15,10:30-11:30;night:21:00-23:00` |
| `slug` | 可选，费率表里的合约 slug（如 `OI505-OI509`），未命中会回落到品种代码 |
| `strategy` | **该价差专属的策略参数**（见 2.1），可以是任意合法策略参数 |

改完 `legs` 后若价差名已存在于 `~/.vntrader/spread_trading_setting.json`，程序会提示 legs
不一致 —— 删掉该文件里对应条目（或整个文件）后重启即可。

### 2.1 每个价差的独立策略参数（`strategy` 段）

策略有 32 个参数，**每个价差可以各配一套**，写在它自己的 `strategy` 段里：

```json
"RM_701_703": {  ...,  "strategy": { "max_positions": 5, "max_hold_days": 10 } },
"J_2611_2701": {  ...,  "strategy": { "max_positions": 3, "max_hold_days": 999, "fee_buffer": 1.1 } }
```

生效优先级（后覆盖前）：

```
策略类默认值  →  spreads.json 的 strategy 段  →  命令行 --setting（临时调试用）
```

三条要点：

- **拼错的参数名会被忽略并告警**：`run_strategy.py --list` 会打印
  `[告警] RM_701_703: strategy.max_position 不是策略参数（会被忽略）`，不会静默失效。
- **`--setting` 是全局的**，会覆盖所有被启动的价差；只想调一个价差就改它的 `strategy` 段。
- **配置是唯一事实来源**：GUI 启动时会按 `strategy` 段为每个价差建好策略实例
  （`CrossPeriodMRStrategy_<价差名>`）。现在通过「查看与编辑策略参数」保存的修改会**写回**
  `config/spreads.json`，不会在下次启动时丢失；只有命令行 `--setting` 是临时覆盖。

历史示例（具体以当前 `config/spreads.json` 为准；条目可能已被增删）：

| 策略实例 | max_positions | max_hold_days | fee_buffer |
| --- | --- | --- | --- |
| `CrossPeriodMRStrategy_A_2611_2701` | 3 | 999 | 1.0 |
| `CrossPeriodMRStrategy_OI_701_703` | 3 | 999 | 1.0 |
| `CrossPeriodMRStrategy_RM_701_703` | **5** | **10** | 1.0 |
| `CrossPeriodMRStrategy_J_2611_2701` | 3 | 999 | **1.1** |

GUI 目前暴露最常用的核心参数（N/M/X、层距、层数、手数、止损、每手保证金、盘口宽度、最小深度、量比、备注）；
`max_clean_width_ticks`、`max_clean_jump_ticks`、`sync_seconds`、`max_hold_days`、`fee_buffer`、
`warmup_days`、执行超时等高级参数仍通过 `strategy` 段配置。

### 2.2 一个合约对的完整操作流程

以新增 `RM_701_703` 为例，从"配好"到"跑起来"共 5 步：

```powershell
# ① 在 config/spreads.json 里加条目（腿 / 主动腿 / 执行器 / stop_loss / strategy），然后自检
.venv\Scripts\python.exe run_strategy.py --list

# ② 采集 + 拼价差 + 策略纸面观察（只连行情，不碰交易端）
.venv\Scripts\python.exe run_strategy.py --md-only --record --minutes 100 --spread RM_701_703

# ③ 只想攒数据、不跑策略
.venv\Scripts\python.exe run_recorder.py --minutes 100 --spread RM_701_703

# ④ 攒够几天后回测（会用到 ②/③ 采下来的 tick）
.venv\Scripts\python.exe run_backtest.py --spread RM_701_703 --start 2026-10-31 --end 2026-11-05

# ⑤ 确认信号与止盈目标价都合理后，真实报单（会连交易前置）
.venv\Scripts\python.exe run_strategy.py --spread RM_701_703 --live
```

每一步都只影响这一个价差（`--spread`），其余价差不受影响。第 ⑤ 步之前的 ①②③④ 都**不会**产生任何委托。

> 非交易时段跑 ②③ 会看到 `[提示] 当前 … 不在任何价差的交易时段内` —— 那不是账号问题，
> 非交易时段订阅成功也没有 tick，部分柜台还会直接拒绝行情登录。

## 3. 执行器：两腿 / 交易所组合单

| | `two_leg`（默认） | `exchange_spread` |
| --- | --- | --- |
| 报单形态 | 主动腿挂限价 + 被动腿对手价 IOC 对冲 | 对组合合约发**一条**价差限价单 |
| 单腿裸露 | 有（主动腿成交后可能短暂裸露） | 无（交易所保证两腿同时成交） |
| 前置条件 | 无 | 组合合约必须已挂牌且在合约列表里 |
| 实盘验证 | 已验证（vnpy 原生两腿路径） | **下单可行已由使用者实盘确认，回报解析仍需账号实测** |

降级矩阵（启动即判定，运行期不再猜）：

| 场景 | 行为 |
| --- | --- |
| `executor=two_leg` | 只用两腿 |
| `executor=exchange_spread` 且组合代码非空、组合合约存在 | 用组合单 |
| `executor=exchange_spread` 但组合代码为空 | 日志告警 + 降级 `two_leg` |
| 组合合约查不到（未挂牌/未收录） | 日志告警 + 降级 `two_leg`（algo 侧也会再兜底一次） |

组合单有三个**必须在实盘账号上确认**的点（`vnpy_ctp 6.7.11.4` 已做好容错，但没有实证）：

1. 成交回报的 `InstrumentID` 是**组合代码**还是**单腿代码**。两种形态算法侧都支持，日志会明确打印
   `成交回报按【组合代码】推送` 或 `按【单腿代码】推送`，第一次成交后即可核对。
2. `CombOffsetFlag` 需要 1 位还是 2 位。默认 1 位（CTP 官方指南的写法）；若被拒，在
   `~/.vntrader/ctp_connect.json` 里手工加 `"组合单偏移位数": 2`（不进 GUI 表单）。
3. 拒单错误码（如 15 = 组合不合法）。algo 日志会记录被拒次数，连续 3 次请人工确认后切回 `two_leg`。

`vnpy_ctp` 三处硬下标已由 `gateway/ctp_spread_gateway.py` 兜住，不会因为组合单回报而 `KeyError`
打断回报线程。

## 5. 逐层止盈

每层开仓/加仓**成交后立即**为**最新层**挂一张止盈单：

```text
目标价差 = 层成交均价 + 方向 × (min_exit_pnl + 该层开平手续费) ÷ (乘数 × 该层手数)
```

- `min_exit_pnl` 自适应 = `max(4 × 单腿单边开仓费, 1 跳金额)`；「元」与「万分之」两种计费都支持。
  5 个推荐品种复现为 J=50、OI=A=B=RM=10 元。
- 手续费按**一层四条腿**汇总：`开(near) + 开(far) + 平(near) + 平(far)`，平今/平昨按**交易日**判定
  （夜盘属下一交易日）。
- 取整方向保守：做多价差卖出止盈**向上**取整、做空价差买入止盈**向下**取整 —— 宁可少成交，
  不让净利低于门槛。
- 只给**最新层**挂一张；平掉一层后自动为新的最新层重挂；老层靠逐层止损/时间止损/换月强平管理。
- 预挂单**不撤单追价**（`timeout=0`），只有**加仓前**与**整仓平仓前**才撤。

平仓优先级（每 tick 至多一条决策）：

| 优先级 | 路径 | 范围 |
| --- | --- | --- |
| 1 | 换月强平（下一交易日任一腿进当月） | 整仓 |
| 2 | 逐层止损（该层浮亏 ≤ `−stop_loss ÷ max_positions`，用**平仓对手价**） | 该层 |
| 3 | 时间止损（持仓交易日数 ≥ `max_hold_days`） | 整仓 |
| 4 | 逐层止盈（预挂单成交） | 该层 |

整仓平仓**必须先撤在挂止盈单并等撤单确认**（超时 3s 告警），否则会"仓已平、单还在"形成反向开仓。
algo 侧还有一层兜底：停止后 15s 未收到撤单确认会强制收尾并告警。

## 6. 行情采集（回测的数据前置）

`vnpy` 收到 tick 只放进内存和事件引擎，**不会自动入库**，所以回测前必须自己采一段。
`run_recorder.py` 负责这件事：订阅两腿合约 → 缓冲 300 条 / 2 秒 → 批量写 `database.db`。

### 6.1 只连行情前置（用真实账号时尤其重要）

采集走的是独立网关 `gateway/ctp_md_gateway.py`：进程里**只有 `CtpMdApi`，没有 `CtpTdApi`**。

| 动作 | 是否发生 |
| --- | --- |
| 连接行情前置、行情登录、订阅 | ✅ |
| 连接交易前置 | ❌ 不创建、不连接 |
| 交易认证 / 交易登录 / 结算单确认 | ❌ |
| 查资金 / 查持仓 / 报单 / 撤单 | ❌（方法直接空实现或返回空串） |

一个实现上的坑：`vnpy_ctp` 的 `onRtnDepthMarketData` 里有一句
`symbol_contract_map.get(symbol)`，取不到合约就**直接丢弃 tick**；而这个字典本来是
`CtpTdApi.onRspQryInstrument` 填的。只连行情时它永远是空的 → 一条都录不到。
所以采集器会用 `register_contract()` 自行注册合约占位（交易所取自 `spreads.json`）。

### 6.2 用法

```powershell
# 1) 只列出将要订阅的合约，不连柜台
.venv\Scripts\python.exe run_recorder.py --list

# 2) 采集 spreads.json 里全部价差的两腿 tick，Ctrl+C 结束
.venv\Scripts\python.exe run_recorder.py

# 3) 只采一个价差，采 30 分钟自动退出
.venv\Scripts\python.exe run_recorder.py --spread A_2611_2701 --minutes 30

# 4) 行情前置临时覆盖（不写回 ctp_connect.json）
.venv\Scripts\python.exe run_recorder.py --setting 行情服务器=tcp://1.2.3.4:41214

# 5) 录 spreads.json 之外的合约
.venv\Scripts\python.exe run_recorder.py --symbols OI701.CZCE,OI703.CZCE
```

**运行前会先做行情前置 TCP 预检**，不通就直接报错退出（不会让你对着「登录失败」瞎猜密码）。
退出时（Ctrl+C 或 `--minutes` 到期）会 flush 剩余缓冲并打印逐合约条数汇总。

### 6.4 两个实测出来的数据精度限制

1. **郑商所（CZCE）不推毫秒**：`UpdateMillisec` 恒为 0，时间戳只有秒级精度，
   同秒的两笔 tick 主键相同 → 被 upsert 塌成一条（实测 OI701 写入 242 条、落库 122 行）。
   影响：CZCE 合约的数据密度约为实际推送的一半（每秒 1 条）。对 3 分钟均值 / 30 分钟
   标准差的信号影响有限，但**不要指望 CZCE 数据有 500ms 分辨率**。
2. **两腿"假不同步"**：因为上面的秒级精度，两腿真实相差 500ms 会被记成相差 1 秒，
   直接按 `sync_seconds=0.5` 卡会把 CZCE 品种系统性误杀（实测 OI/RM 全部被 `S0.5` 拦掉）。
   过滤器已做**精度自适应**：两腿时间戳都是整秒时，阈值放宽容纳 1 秒
   （`utils/filters.py::FilterChain.sync_ok`，有单测覆盖）。

另外 `dbtickoverview.count` 记的是**累计写入条数**（`stream=True`），同键覆盖会虚高；
真实行数以 `dbtickdata` 为准，回测读的也是 `dbtickdata`。

### 7.1 三个必须知道的坑（都踩过，都已修）

| 坑 | 现象 | 原因与修复 |
| --- | --- | --- |
| **价差引擎没启动** | 行情面板有 tick、数据库也在涨，但策略一条 `on_spread_data` 都没有，价差永远是 0 | `MainEngine.add_engine` **只创建引擎、不调 `start()`**；`SpreadDataEngine` 是在 `start()` 里才注册 `EVENT_TICK` 的。GUI 靠价差面板代劳，命令行必须自己调 → `utils/engine_setup.py::ensure_engine_started` |
| **时区混用** | 日志一句 `触发异常已停止`，之后策略彻底不响应，但进程照常收行情 | 一腿 tick 带 `Asia/Shanghai`、另一腿是 naive（回测自造的 tick 天然 naive），`max(near, far)` 抛 `TypeError`；而 `call_strategy_func` 会**吞掉异常并把策略静默置停** → `utils/filters.py::as_local` 统一时区 |
| **价差配置被覆盖** | 面板/配置里本来 4 个价差，某次运行后只剩 1 个 | `add_spread(save=True)` 会把**当前内存里的全部价差**写回文件；若引擎没 `start()`（没 `load_setting`），内存里只有刚加的那一个，写回就把其余冲掉 → 必须"先 `start()` 再 `register_spreads`" |

顺带加了两处运维兜底：`run_strategy.py` 每 10s 检查策略是否被引擎静默停掉并告警；
`SpreadSnapshot.build` 对两腿时间戳做时区归一。`tests/test_wiring.py` 现在会断言
`spread_engine.active`（引擎真的启动过）。

**数据前置（硬要求）**：两腿各自的 tick 必须在 vnpy 数据库里（默认 `~/.vntrader/database.db`）。
注意 `vnpy_spreadtrading` 自带的回测引擎读的是**以价差名字入库的合成 tick**（`symbol=价差名,
exchange=LOCAL`），本仓库的 `backtest/engine.py` 改成**直接读两腿 tick 在内存里合成**，

回测与实盘的差异（结果需打折理解）：

| 项 | 回测 | 实盘 |
| --- | --- | --- |
| 止盈成交 | 触价即成交，成交价按当时对手价 | 排队，可能长期不成交（大商所套利单优先级低于单边） |
| 两腿同步 | 同一条合成 tick 同时成交 | 有先后，可能单腿裸露 |
| 手续费 | 按单腿 `FeeCalculator` 逐笔计费（与实盘同口径） | 同左，但仍不含期货公司加收 |
| 组合单 | 不模拟 | 由交易所撮合 |

回测引擎已覆写 `calculate_result`：手续费按 `元 / 万分之` + 平今/平昨逐笔计算，不再用
`turnover × rate` 的近似值（否则 `min_exit_pnl` 的校准会失真）。
