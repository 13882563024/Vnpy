# 交易重写：如何在不连接柜台的情况下核查一笔决策

在仓库根目录，用项目虚拟环境运行；以下路径是占位符。命令只读指定的既有 SQLite 事实库，不调用下单 API。找不到库会报错，不会在错误路径新建空库。

```powershell
.\.venv\Scripts\python.exe -m tools.replay_ctp_facts '<已有事实库路径>' --day 20261119
.\.venv\Scripts\python.exe -m tools.replay_ctp_facts '<已有事实库路径>' --day 20261119 --account '["broker","investor"]' --decision '<策略名>' '<稳定决策号>'
```

第二条仅适用于确实记录了策略意图和关联的决策；历史 CSV、手工单不会被猜配。输出包括意图及触发依据、发送前绑定、柜台委托、成交事实和冲突序号。`reserved_only` 是仅预留；`send_result_unknown` 是已绑定本地报单身份但尚无柜台委托证据；两者都不能据此重发。`broker_reported` 表示收到关联柜台回报，不等于全成，更不代表已完成所有腿和层级的核对。`needs_review` 表示归属/明细矛盾。各腿成交条数不是组合手数。在第二条命令追加 `--legs a2701 a2703`（替换为该意图真实的近、远腿）可查看本地已配对组合量、实际价差均价、未配对余量，以及“柜台已报成交、明细尚未齐”的状态。缺少证据用 null，不用 0 冒充。

## 打开只读工作台

仅查看仓库配置：` .\.venv\Scripts\python.exe run_workbench.py `。若要加载正在写入的 SQLite 事实库，不能直接只拷贝主文件（已提交页可能仍在 WAL）。先导出一个新快照，再用工作台打开；这些命令不会连接柜台，也不会替换源库。输出目录须支持硬链接，已有快照不会被覆盖。

```powershell
.\.venv\Scripts\python.exe -m tools.export_fact_snapshot '<已有事实库路径>' '<新快照路径>'
.\.venv\Scripts\python.exe run_workbench.py --facts '<新快照路径>'
```

影子快照单独通过 `--shadow` 指定，不能冒充柜台成交。工作台是离线快照，不是实时柜台授权。

## 用可复现示例走一遍新策略和工作台

[豆一合成示例](../../examples/replay_bean.jsonl)不是实盘记录。先输入 30 个仅供预热的报价，随后放入允许开仓的偏离报价；再显式给出已归属、已配对的成交与终态，最后给出本层费用估算。引擎不会把“价格触及限价”当成实际成交。

```powershell
.\.venv\Scripts\python.exe -B run_spread_replay.py --spread A_2701_2703 --account paper-demo --events examples/replay_bean.jsonl --output bean-shadow.sqlite
.\.venv\Scripts\python.exe -B run_workbench.py --shadow bean-shadow.sqlite
```

输出文件必须是新文件。预期是一个开仓意图、一个顶层止盈意图：实际开仓成本 −9，假定四边费用合计 8 元，净目标 10 元，乘数 10，保守取整后止盈价 −7。尚未收到止盈成交，所以最终剩 L1 一手。工作台中的结果标记为影子来源，不得作为实际柜台仓位。

`quote` 提供两腿顶档和当时的会话/资金等检查结果；`matched` 仅接收已确认归属的累计配对明细，不能填预期成交；`working`、`unknown`、`terminal` 是原订单的回报，`protect` 提供逐层费用；用 `decision_event` 指向产生该意图的输入事件 ID。原始柜台流水应使用前述只读工具，不能直接当影子输入。

## 预览参数与隔夜核对

`python -m tools.draft_spread_config --spread A_2701_2703 --set entry_k=0.5` 只打印差异与版本摘要。加 `--export <新路径>` 可导出草案供回放的 `--config` 使用；不允许修改账户、腿映射、实时开关，也不覆盖任何已有文件。草案不是运行中策略的参数变更。

`python -m tools.audit_rollover --help` 列出隔夜审计参数。需要有版本匹配的配置、上一交易日最终且闭合的完整查询及次日未开始交易时的完整查询，账户键/交易日/查询令牌必须一致；前一交易日来自柜台交易日历，不可按自然日猜测。只存过摘要或缺腿价证据的旧数据不能靠当前净仓倒推出已知层成本。审计给出差异/复核步骤，即使一致也不授予实盘许可。

## 离线验收

```powershell
.\.venv\Scripts\python.exe -B -m unittest tests.test_layer_book tests.test_layer_replay tests.test_paired_fills tests.test_decision_trace tests.test_preflight
```

- 加仓实际成交才撤旧顶层止盈；两张单都成交时只保留新实仓，即使回报顺序颠倒。
- 终态累计与已配对明细未对齐时不补发。单个组合委托两腿各一手只配成一手；多余的未配对腿单独显示，不进入已配对的成本。
- 交易日切换后仍可重放原有层；只重建视图，不重新发送历史动作。部分成交后撤余量、存续层顺序重排目前为影子回放策略。
- 下单核验绑定账户、决策内容、会话、状态版本和时限；同一证据不能用两次。测试中的柜台查询与发送均为替身，不能据此证明实盘查询速度、完整性或授权。
