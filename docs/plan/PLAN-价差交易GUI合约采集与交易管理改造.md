# 价差交易 GUI：单字段添加合约、自动采集与多合约交易管理改造方案

> 状态：待确认方案，尚未实施；面向本仓库的 VeighNa / Qt「价差交易」窗口，不改变既有策略信号公式。用户入口以 `DCE.SP a2701&a2703` 为例。

## 1. 目标和可见行为

- 用户在「功能 → 价差交易」点击「添加合约」，仅输入交易所及完整组合代码，例如 `DCE.SP a2701&a2703`，确认后列表立即出现一项；不要求填写腿、公式、乘数、组合名、策略类和订阅代码。
- 新增即自动解析近月 `a2701.DCE`、远月 `a2703.DCE`，自动注册价差、订阅两腿并录制 tick；组合行情显示近月减远月的 bid / ask / mid。**采集和交易是不同状态**：全局交易关闭时照样采集。
- 左侧可选择多个合约；右侧随所选合约切换「实时价差 / 采集状态 / 配置与风控 / 当前持仓与挂单 / 最近决策」。每合约有独立「允许交易」开关，顶部有「开始交易 / 停止交易」总开关和已就绪/运行/异常数量。
- 只有总开关开启、该合约允许交易、交易端就绪、数据新鲜且风控通过时，已有 `CrossPeriodMRStrategy` 才能对实时合成价差 tick 作出挂单/不挂单、开仓/平仓、价格/手数的决策。UI 不另写一套交易算法。
- 「停止交易」严格解释为**暂停该范围内的策略决策和策略动作，不新发单、不改价、不撤单、不自动平仓**。已有委托原样留在柜台，可能继续成交；已有持仓和在途委托仍在界面显示和被动接收回报，但**策略不依据回报继续执行**。明确标记「策略已暂停，挂单仍可能成交，持仓未受自动风控保护」；采集与行情显示不停止。另设「只平不开」作为独立交易模式，不把停止交易解释为继续自动平仓。真实委托仅能从明确确认的实盘模式发出。

## 3. 添加合约：解析与注册事务

1. 对输入只做边界空白清理，分离前缀交易所 `DCE` 和**原样保留**的组合 `SP a2701&a2703`；内部 `vt_symbol` 转为当前 vn.py 惯用的 `SP a2701&a2703.DCE`。不得将用户输入的 `DCE.SP ...` 直接传给 `extract_vt_symbol`，也不应自行重新拼写组合代码。
2. 为支持的交易所维护明确语法解析器（首批 DCE `SP <近月>&<远月>`；其他交易所如 CZCE `SPD ...` 经独立规则和测试后开放）。校验前缀、单个 `&`、同品种、月份顺序、唯一性、非过期、输入长度；不能解析或不支持时**拒绝添加并解释原因**，不得猜测交易所规则。
3. 解析所得两腿为 `a2701.DCE`、`a2703.DCE`；变量必须叫 `near` / `far`，`price_formula=near - far`，交易方向和乘数分别为 `+1/-1`，主动腿默认近月；显示名保留完整 `DCE.SP a2701&a2703`，内部稳定 ID 与展示名分离。乘数、tick、时段优先查询柜台腿合约，缺失时可读取经验证的本地品种表；未经确认不启用实盘。
4. 应用服务先创建待验证草稿，若 CTP 当前未连接，列表显示「待连接验证」，允许保存与采集意图，但**交易开关禁用**；连接后核对两腿合约与组合合约是否真实存在、交易所和乘数一致。若组合合约不可用，标记「不可组合单交易」；只有手动选择两腿执行并确认裸露风险后才可能解锁。
5. 校验成功后原子持久化条目（先临时文件、校验、替换，失败回滚），调用价差数据引擎注册并建立/更新唯一的策略实例；订阅两腿并建立录制引用。任一步失败都保留明确错误状态并回滚未完成的持久化/引擎动作，禁止出现“列表已显示可交易，但策略未创建”。重复添加应定位已有条目而非复制。
6. 编辑参数在所选合约详情页进行：执行器（组合单/两腿）、每层手数、最大层数、逐层止损、时段、统计窗口、阈值、费率缓冲、只平不开等按分组呈现；高风险项改动须停策略、校验后再生效；不让 GUI 编辑值在重启时被 `spreads.json` 覆盖。

## 4. 采集与实时数据链

```text
添加合约 → 解析并持久化 → 订阅近/远月（同腿共享） → EVENT_TICK
                                             ├→ TickRecorder → database.db（两腿原始 tick）
                                             └→ SpreadDataEngine → 价差 bid/ask/mid
                                                                   └→ 策略 on_spread_data
```

- 录制的是**两腿原始 tick**，不是 `DCE.SP ...` 的直接行情；合成价差由 `near_bid − far_ask`、`near_ask − far_bid` 及 mid 得到，延续现有回测/策略口径。
- 新合约立即动态订阅；已共享的腿不重复订阅。连接尚未就绪时标记「等待订阅」，交易端恢复后重试并校验最后 tick 时间、两腿报价与可成交量。动态录制名单为空时沿用现有「全部收到 tick」模式；非空时增量加入新腿并记录采集状态。
- 详情显示两腿各自的订阅/最新 tick 时间、入库条数、合成报价与数据时间差；价差不更新时给出具体阻断原因。行情断线、报价过期、缺深度/不满足过滤器时**不发新开仓单**；风控平仓如何执行必须建立在可用行情及可靠柜台连接之上，故障时告警而不凭旧价猜单。
- 历史查看沿用「功能 → 行情数据」，在合约详情增加快捷入口，并让新添加的价差在浏览器中动态可见（当前浏览器价差名单取注册表）。

## 5. 多合约交易门禁与状态

最终发单许可在**引擎/执行层**检查，而不是只在 Qt 按钮里禁用：

```text
allow_new_order = master_running
               ∧ contract_enabled
               ∧ live_confirmed
               ∧ ctp_td_ready
               ∧ contracts_verified
               ∧ quote_fresh_and_valid
               ∧ strategy_initialized_and_running
               ∧ risk_passed
               ∧ !circuit_breaker
```

- 默认 **总开关关闭、各合约交易关闭、`live_trading=False`**；重启后总开关必须再次人工开启，防止无意识自动复盘。各合约启用意图可持久化，但在总开关关闭时不发单；启动前显示本次将启用的合约、执行器、账户和风控摘要并二次确认。
- 添加合约即开始采集；「总开始交易」只启动**已单独启用且就绪**的策略，不影响未启用项。若部分合约不合格，给出逐项阻断原因；不允许把“部分已启动”显示成“全部已启动”。全局/单合约「停止交易」只对对应策略设置暂停门禁：不调用现有会撤委托的 `on_stop` / `stop_algo`，不停止采集，不撤在途委托，不主动平仓；移除有持仓或未决委托的合约须阻止，先处置风险再移除。
- **暂停期间的异步回报**：CTP 订单、成交回报照常进入 OMS、录制与审计日志，必须按委托 ID 记录新增成交及仓位变化；但不得触发该策略的跟单、补挂、撤挂、止盈/止损或其他新动作。若两腿算法有主动腿成交、被动腿尚未对冲，暂停后不得继续自动对冲，界面须突出「裸腿风险，需人工处理」。该语义不能只在 Qt 按钮上禁用，必须在策略事件回调与算法计时器/发单入口设暂停门禁，并保证竞态下暂停生效后无新策略委托；保留挂单的撤单/过期行为若受柜台自身规则影响需照实反馈。
- 「只平不开」为明确的第三种状态：禁止开/加仓，已持仓允许在行情和柜台可靠时按策略平仓；它与「停止交易（策略完全不执行）」严格区分。切换全局/单合约开关与 `live_trading` 不能仅依赖编辑 `SpreadStrategyTemplate.trading` 属性。
- **恢复交易不是无条件解冻旧算法**：先查询柜台全部在途委托及单腿持仓，结合暂停期间成交核对本地层账，核验挂单目的/剩余量、当前行情与风险阈值；有不一致时保持暂停并交由人工处理，不能复用暂停前的旧目标价直接继续发单。现有策略层记录在内存中，单凭价差净仓不够恢复逐层止盈/止损，须补持久化和对账流程。断线/重启亦回到交易停用/待核对，**不自动撤销用户要求保留的在途委托**；回报形态不明或组合口径未验证则阻断新开仓。
- 组合单真实回报及偏移位数尚需账号联调；将其作为上线阻断项和明确验收门槛，不以模拟成交替代。交易所组合合约无法查询时不能静默退到有单腿风险的 `two_leg`。

## 6. GUI 布局与操作流程

| 区域 | 内容与动作 |
| --- | --- |
| 顶栏 | CTP 行情/交易连接状态、采集状态、总交易状态、已启用数量；主按钮「开始交易」或「停止交易」，停止提示「保留委托；仍可成交；策略风控暂停」 |
| 左侧列表 | 「添加合约」；每行完整组合代码、最近价差、录制状态、独立交易开关、阻断/异常标志；切换仅改变详情选择，不隐式开启交易 |
| 右侧概览 | 当前价差 bid/ask/mid、时间与两腿 tick 新鲜度、策略决策（开/平/等待及原因）、持仓层数、在途委托 |
| 右侧配置 | 用户可读的近/远腿（自动推导、只读）、执行器与交易参数（分组可编辑）；可见默认值、修改后需重启的字段及来源 |
| 操作反馈 | 添加成功/待验证/不支持格式/无合约/订阅失败；总开启前逐合约检查表、二次确认；暂停后持续显示在途委托、可能成交与未自动保护持仓的告警 |

**典型流程**：连接 CTP → 添加 `DCE.SP a2701&a2703` → 看到自动识别的两腿和实时合成价差、tick 已入库 → 检查并保存该合约配置 → 开启该合约「允许交易」 → 总「开始交易」复核并确认 → 观察策略决定与委托/成交 → 总「停止交易」后仍可查看原委托与后续成交，但策略不再执行 → 恢复前核对柜台委托、仓位和策略层账。用户不需接触 JSON 或 CLI。

## 7. 分阶段实施与验收

1. **配置/解析服务**：新增组合代码解析、字段推导、持久化与唯一 ID；迁移已有 `spreads.json` 条目和 vn.py 已保存价差，不改现有价差语义；DCE 样例/非法输入/重复/冲突有单测。
2. **自有 GUI 页与动态采集**：在 `main.py` 中挂自有价差管理窗口（不要修改 `.venv`）；新增/切换/编辑多合约，注册后动态订阅共享腿、录制 tick、合成报价；用模拟行情测试选中项、断连及重连状态。
3. **交易总控与逐合约门禁**：引擎侧原子暂停状态、不撤单的策略/算法回调门禁、只平不开、执行器选择优先级与禁止隐式降级；用 fake gateway 模拟暂停前在途委托、暂停后成交/部分成交和两腿未完成对冲，证明暂停后无新单/撤单/改单/策略决策而旧委托仍存在，多合约只启动就绪项。
4. **持仓恢复与实盘放行**：层账持久化和重启柜台对账、拒单/成交/撤单竞态；先纸面运行及模拟下单，再小手数账号验证组合单回报、偏移标志、平仓与风险事件，最后开放真实交易。

**完成标准**：全程 GUI 一字段添加两份不同跨期合约，两个价差实时更新且各自两腿 tick 入库；切换详情不串参数；总开关与每项开关组合形成预期发单集合；停止交易后既有委托保持原样、行情与订单/成交监控继续，策略无决策及新委托/撤单/改单，暂停后成交能计入待核对状态；重启不会自动实盘交易，持仓未核对不可恢复交易；错误、断线和未挂牌组合单不会隐式变成两腿下单。

## 8. 本方案需确认的产品决策

- **总「停止交易」——已由用户确认**：停止策略执行，不产生策略新委托/撤单/改单，不撤销现有委托、不自动平仓；现有委托可能继续成交，持仓不受策略自动止损保护。行情采集及订单/成交状态监控继续；恢复前对账。需要自动平仓时应明确切到单独的「只平不开」模式，而非「停止交易」。
- **默认执行方式**：本方案拟以“交易所组合单”为目标方式，但在组合未获柜台证实前锁定实盘；两腿模式只能显式选择并确认风险。既有条目的执行模式保持不变。
- **交易端连接**：新增/采集可在交易端未就绪时准备，但仅行情连接是否足以自动识别该组合合约及乘数取决于柜台/本地元数据；未验证字段一律阻断实盘。
