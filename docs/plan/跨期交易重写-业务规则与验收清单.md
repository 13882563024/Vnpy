# 跨期交易重写：业务规则、模块边界与验收清单

评审稿 · 2026-11-19。本文是实施规格，不是已上线功能。范围：同品种、同乘数、近远月 1:1 的交易所原生跨期组合。继续使用 vn.py/CTP 收发事件；不把 vn.py 内存对象或界面状态当作策略账本。不支持的组合只观察，不静默切换成两腿分开发单；独立两腿执行若要开放，另行验收裸腿风险和对冲。本文中的盈利均是目标或估算，不是成交或盈利保证。

## 1. 先确定哪些业务规则变、哪些不变

|事项|旧行为或现状|本次规格|
|---|---|---|
|进场|双窗口价差均值回归，偏离越深才开更高层|保留方向、严格不等号、实际参数及过滤逻辑，给每次决策留数值证据|
|加仓换止盈|实际代码在加仓**前**先撤旧止盈|按新要求：旧顶层止盈在加仓等待期间仍有效；加仓**实际成交**才发起换单。必须处理两单同时成交，以及旧单撤不掉的情形|
|止盈对象|目标按层；常态只挂最新层|保留；绝不按整仓均价给最新层算目标。低层暂不挂单是策略设计，不是委托丢失|
|事实来源|柜台、OMS、策略层、恢复缓存各自改状态|柜台回答“账户实际发生了什么”，本地成交账回答“归哪个策略哪一层”，对账判断两者是否能互相解释；未知不视为零|
|启动方式|GUI、命令行、定时恢复路径不同|所有入口只能提交意图；一个发单门禁。定时任务不拥有额外交易或强制纠正权限|

## 2. 策略计算合同（独立、可回放、无交易 API）

**2.1 行情与统计。** 记近、远腿最优买卖为 bN/aN、bF/aF，价差方向固定为近减远。信号价 S=(bN+aN)/2−(bF+aF)/2；合成买一 B=bN−aF，合成卖一 A=aN−bF。做多组合=买近卖远，入场参考 A、退出参考 B；做空反之，入场 B、退出 A。这三种价格以及交易所组合盘口、实际成交价须分别记录，不能互相冒充。价差可为负也可为零；缺失值用 null，不用 0。

- μ 为最近 `mean_window_minutes` 分钟 S 的算术均值。σ 为最近 `sd_window_minutes` 分钟的**样本**标准差：σ²=Σ(Sj−μ长窗)²/(n−1)。方差中心是长窗自身均值，不是短窗 μ。z=(S−μ)/σ。按 tick 采样，不是分钟 K 线也非时间加权。旧代码在可交易时段先纳入当前样本再判定，并以快照时刻去重。
- 建议新版只让通过基础质量检查的样本进入统计，区分真重复与同毫秒的不同 tick；保存两腿输入事件号、采样版本。此处会改变历史信号，必须做新旧样本对拍，不能称为等价移植。默认预热条件是长窗至少 30 个样本、首尾跨度至少 5 分钟，且 σ>0；预热只拦开仓，不拦已知持仓的风险处理。
- 下一层 i 的门槛 Ki=`entry_k`+`layer_step`×(i−1)。空仓时 z<−Ki 做多，z>Ki 做空，等于不触发；有仓只允许沿当前方向使用同一规则加仓。当前实现的 i 是最高存续层序号+1，不是历史累计成交次数。新版将**永久层 ID**与**当前阶梯序号**分开：有非顶层缺口或双成交导致序号歧义时，先归账再重排当前阶梯或冻结，不能直接开出超限层。每次只发一个意图，不因一次跳价跨过多个阈值而批量下单。
- 豆一配置实例（非全品种默认）：窗口 3/30 分钟，`entry_k=0.3`、`layer_step=1.0`、上限 3 层、每层 1 手，所以三道门槛为 **0.3σ、1.3σ、2.3σ**。类默认参数与合约覆盖不同；决策和 UI 均显示最终生效值和配置版本。
- 入场门槛以外还要逐项验证：交易时段、可开仓、合约挂牌、腿报价有效且未倒挂/越涨跌停、突跳清洗、单腿盘口宽度、两腿报价时间差、四个一档挂量最小值、可选成交量比 max(vN,vF)/min(vN,vF)、近交割月禁止开仓、资金与额度。豆一示例宽度参数 2 tick（旧实现另有半跳容差）、最小深度 1、同步参数 0.5 秒、成交量比过滤关闭、距合约当月约 3 个交易日内禁开。旧同步检查对两腿整秒时间另加 1 秒容差；新版缺时间不放行，另验两腿相对现在均不陈旧。交易日与合约日历不按自然日切换。

**2.2 逐层目标。** d=+1 为多价差、−1 为空；E 为**本层实际开仓价差加权均价**，q 为参与本次止盈的剩余组合手数，M 为每点每手金额，τ 为组合最小价位。

1. 四边费用 F=缓冲系数×(开近+开远+平近+平远)。固定收费每边=元/手×q；比例收费每边=|腿价|×M×q×费率/10000。平今/平昨按交易日。挂单前未发生的平仓费用只能估算，结算用实际费；部分平仓分摊已付开仓费，不能重复扣。缺实际腿价不得用盘口伪造，费率或成本不确定时标记估算，达不到预设可信度则不自动挂。
2. 最低净盈利 G：若 `min_exit_pnl_override>0` 用覆盖值，否则 G=max(4×近远腿中较高的**一手单边开仓费**，M×τ)。原实现 G 是每层金额，不随 q 自动倍乘；多手层或部分成交后是否按手分摊目标是配置语义，不能默改。
3. 原始目标 T*=E+d×(G+F)/(M×q)。默认保守取整：多仓卖平 T=ceil(T*/τ)×τ，空仓买平 T=floor(T*/τ)×τ。旧代码也支持最近价位；若新系统承诺扣费后至少达到 G，应禁用不满足复算条件的取整。限价被确认受理≠成交。
4. 算例（费用为示例）：E=−12，M=10，q=1，τ=1，G=10 元，四边合计 F=8 元。多仓目标 −10，空仓目标 −14。按目标成交时两者估计净收益均为 2×10−8=12 元。第二层有自己的 E，不借用第一层成本，也不是在第一张止盈单上增加一手。

**2.3 风险退出。** 现有优先级：换月整仓退出 → 逐层金额止损（由最新层向下找首个触发层）→ 时间止损整仓 → 常态顶层止盈。逐层浮盈亏 U=d×(P退出−E)×M×q；多用 B，空用 A；启用止损且 U≤−该层止损额才触发，这是毛浮亏口径。当前每层止损额=生效的整仓止损金额/max(1,最大层数)，不是把整仓金额重复赋给每层。时间止损从最早存续层的开仓交易日计，达到 `max_hold_days` 退出。豆一配置设有止损金额但 `allow_stop_loss=false`，不能显示成“止损已开启”；换月退出参数为 1 个交易日。整仓退出从高层向下扣实成量；挂单冲突时先撤冲突单，按已确认可平余量执行。只平不开不等于无风险；暂停保留旧单、撤单、主动平仓分别是三个命令。

## 3. 三层状态机：一次加仓允许两张不同用途的单，不允许两张止盈

|现态|事件|必须执行|禁止执行|
|---|---|---|---|
|空仓|首层信号且门禁通过|预留 1 层容量，提交 L1 开仓意图|未成交先建实仓或挂止盈|
|L1 已成交|账实可解释、无对应平仓占用|只挂 L1 的限价止盈|把两腿各成交 1 手算成 2 手组合|
|L1 止盈在柜台|L2 信号有效|保留 L1 止盈，至多提交一张加仓单；拒单或零成交撤单仅释放加仓预留|信号一出先撤 L1 止盈；重复 tick 再开一张|
|L2 已成交|L1 止盈仍在|记入 L2，冻结新加仓，撤 L1 止盈；收到旧单确定终态且相应明细齐全，重算后仅挂真实顶层的剩余量|撤单请求已发或超时就先挂 L2；同时挂两张止盈|
|L1+L2 → L3|第三层信号|与上行相同；实仓加未决开仓的最坏数量不能超过 3 手|满层继续加仓；止盈一报出就当层已释放|
|L3 止盈成交|部分/全部平仓|部分成交只扣 L3 对应手数；全平后才恢复 L2 止盈，再退回 L1|一笔成交关闭两层；恢复已平层|
|最后一层平完|所有相关单均已终结且明细齐|空仓，解除方向锁；下个有效信号可多可空|仍有待确认的原方向开仓单便反向开仓|

**两单竞态须作为正常业务处理。** 若旧止盈先成交而加仓仍挂，立即请求撤未成加仓余量，不把撤请当撤成；仍到达的真实成交照记原意图，不丢弃。若两单都成交，按各自永久层 ID 入账：L1 已平、加仓实际成 1 手，则净剩一层，不是空仓或两层。等待冲突单终态及明细齐全，重算方向、阶梯与可平量，再挂唯一顶层止盈。切换期允许短时 **0 张**止盈，应显示原因和持续时间，超时冻结加仓并告警，不能伪造保护。部分加仓建议首笔确认配对成交即记新层，后续同意图成交合并到同一层；冻结后续加仓，撤未成余量并核定最终数量后换止盈。若交易所自成交防范或账户规则不允许保留旧单同时加仓，阻断该加仓并告警，不偷偷改回先撤旧单。

## 4. 模块清单（模块边界先于目录名）

|模块 / 唯一职责|输入 → 输出|禁止事项|
|---|---|---|
|合约与配置|合约目录、腿映射、乘数、交易日历、手续费、策略/风险配置 → 校验后的版本化参数|配置的允许交易不等于已获当前会话许可；持仓期间改参数须预览对存续层的影响|
|行情与统计|原始腿/组合 tick → 带时间、深度、质量及来源的价差快照、μ/σ|不发单；不以报价代替成交|
|信号与层级策略|快照+层账只读视图 → 开、加、止盈、风险退出或不操作的意图与理由|不直接调用 CTP，不直接加减持仓|
|订单与执行|已批准意图 → 持久化预留、唯一委托、撤改请求及状态|撤单超时≠已撤；平仓量不足不许转反向开仓|
|CTP 适配器|原始报单、异步回报、委托/成交/持仓/资金查询 → 原样留存及标准事件|不为修复 UI 自造 ALLTRADED；不合并两个腿手数冒充组合手数|
|成交与层账|去重的事实事件+归属 → 各层实成/剩余、手续费、已实现盈亏|不凭信号建层；不以账户持仓均价补写某层真实成本|
|核对与纠正|完整柜台快照+事件日志+本地投影 → 差异、证据、可逆纠正方案|核对只读；纠正只改本地投影，不代替撤单/平仓，不自动接管手工仓|
|账户风险与发单门禁|账户资金、各策略预留、持仓/委托可信度 → 一次性许可或阻断原因|Qt、CLI 和定时器都不能绕过；共用腿和资金按账户统筹|
|持久化与回放|行情、事件、决策、参数、快照 → 可重建的视图和审计查询|磁盘旧状态不可覆盖较新的柜台终态；存储不可写时禁新风险|
|工作台、报表与调度|上述只读视图 → 用户可见状态；人工或定时操作 → 同一个应用命令入口|不在界面线程改 OMS 字典、不靠打开窗口才开始风控、不定时强制认领|

实现建议：每个账户只允许一个实盘写入者（防 GUI/CLI 双开）；按账户串行预留，对同价差状态变更排序。命令、原始事件、账本投影分离；事件可重复到达，记账结果不可重复。崩溃在“本地已记意图、CTP 是否收单未知”之间时，标成发送结果未知，先查证而非重发；数据库事务不能保证外部交易恰好一次。

## 5. 对账协议：开每一张单之前，具体检查什么

- [ ] **标识映射。** 本地永久 `intent_id/order_id/tier_id`；发送前落盘本地关联和请求号。会话内以 Broker/Investor + TradingDay + FrontID/SessionID/OrderRef 关联；获柜台回报后再绑定账户、交易日、ExchangeID、OrderSysID 作为跨会话查找依据，保存原值并按接口规范正规化。交易所单号不是全市场永久唯一，未获单号也不代表没发出。成交去重键含账户、交易日、交易所及成交标识，核实各柜台组合/派生腿标识粒度，必要时纳入合约/腿等区分字段。冲突隔离，不猜归属。
- [ ] **启动、重连、日切、定时和每单前**均经过同一核对服务。每次报单（含止盈/改挂）前要求本轮柜台核验完成：排队限流查当日委托、必要成交明细及两腿持仓；校验账户、交易日、请求号、最后一包、查询错误及查询期间的新事件。并发意图可合并同轮查询，但不可用“5 分钟内曾经核对过”代替本次检查。查询慢则等待并重验信号/价格；若业务以后接受有时效上限的事件增量门禁，作为另一个明确授权的策略，不默认降级。撤风险的撤单走独立通道，不因无法新增报单而连撤单也封住。
- [ ] **委托。** 柜台“当日有此单”不代表仍活跃：读状态、累计成交和剩余。已撤/拒绝/全成与待撤/部成分别处理；终态累计大于本地已入账量时进入“终态已知、明细待齐”，继续收迟到成交，不释放可重报额度。查询限流、未收尾、不可解析、范围不覆盖原交易日都只能得出“未知”。完整查询亦需结合成交和结算边界解释失踪单；不以缺一行直接宣告零成交已撤。柜台有、本地无：记录外部/待认领，冻结受影响范围。
- [ ] **持仓。** 一层 d、q 投影为近腿 +d×q、远腿 −d×q；按账户、交易所、合约、方向、今昨及必要的投保分类分别汇总。核对等式为：策略已归属 + 已识别外部仓 + 待解释项 = 柜台对应腿持仓；待解释项非零不能自动放行。不能只比较净仓：多 1 空 1 不等于双边空仓。共用腿时跨策略汇总一次，不能把同一条柜台持仓分给两个价差。归属只由可追溯成交证明，不由数量凑齐证明。
- [ ] **发单门禁。** 在同一状态版本检查连接/会话、完整快照、交易时段与报价、信号仍成立、唯一意图、无未决冲突、额度和可用资金；平仓量不得超过本层剩余与两腿可平量。预留按最坏在途量，含待撤及回报未知；已被柜台冻结的量与本地预留不可重复扣。版本变化即失效重验。外部终端随时可能交易，查询与发送不是柜台原子操作；专用策略账户或外单影响立即冻结是最后防线。
- [ ] **自纠正分级。** 可自动：补录唯一关联的柜台回报、忽略幂等重复、按原始事件重建投影。须人工：历史单归属不唯一、共用腿不明、账外仓、缺层成本、腿未配对。先显示差异和纠正前后预览，再记录操作者、证据、版本和结果；确认查看≠修正≠恢复发单。不能用柜台整仓均价推断某个遗漏层。暂停与显式人工应急处置保留审计。

## 6. 必须留下的数据

|记录|最少可复盘字段|
|---|---|
|行情|交易日、交易所/接收时间、事件序号、近远腿和组合原始盘口/量、合成 B/A/S、质量标记；批写 tick 并标明缺口|
|策略决策|决策/周期 ID、价差、层 ID、输入 tick ID、参数版本、μ/σ/z/K、各过滤实测值与阈值、目标/可平量、费用拆解、门禁版本、触发/拒绝原因。例：L2 多向 z=−1.41<−1.30，深度通过，L1 止盈仍有效，申请加 1 手|
|订单与事件|关联意图、策略、层、账户、人工/自动来源、组合或腿、方向开平、数量/价格、会话及柜台 ID、原始回报、请求/应答时间、状态流转、累计与剩余、失败码/文字、撤改前后关联。未发送即被风控拦截也保留意图，不伪造柜台委托|
|成交与持仓层|永久层 ID、阶梯序号、方向、计划/配对实成/剩余量、逐笔腿/组合真实成交及均价、信号价差/限价/成交价差分别存、开平时间及交易日、估算/实收费用、止盈目标和订单、关闭原因、配置版本。只有组合价而没有腿成交价就标未知，待补证；组合回报与两腿明细不可双记|
|对账与收益|每轮请求、快照范围/完成标志/时刻、差异与审批；账户权益/可用/保证金/冻结快照；按层、价差、交易日汇总已实现、未实现、费用、净收益。记录原始→标准化事件版本；不存口令。定期备份并做恢复演练|

策略已实现毛收益=Σ d×(实际平仓价差−对应层开仓价差)×M×实际平仓量；净收益扣归属费用。未实现按当前可退出价估值并标行情时刻；全账户权益变动还含出入金、结算口径、手工和其他策略，不能直接当本策略收益。日终以结算账单核验实际费用和账户口径差异。

## 7. 工作台：先回答“现在能不能发单，为什么”

- **账户栏**：账户/交易日、行情与交易连接、权益/可用/保证金/冻结、当日与累计收益（账户/策略分开）、最后完整核对时间、当前自动发单权限。
- **合约总表**：每个已添加价差一行：方向、层数/上限、组合实仓、柜台逐腿、顶层止盈“已确认量/应挂量”、开仓在途量、账差、阻断原因。例：`豆一｜多 2 层/3｜顶层应挂 1，已确认 0｜旧止盈待撤 1｜禁止继续加仓`。不用“无敞口”代表“账实一致”。
- **选中合约详情**：按层显示实际价、两腿成交、时间、目标价、实收/估算费用、盈亏和关联订单；低层显示“非顶层，按策略不挂”。订单分为柜台活动、状态未决、历史终态、外部待认领。点单能追到触发公式、参数快照、撤单原因和原始回报。
- **日志和异常**：实时流可按价差/层/委托/严重度筛选；断线、持仓不符、止盈未覆盖、撤单未确认置顶。旧数据带“截至时间”；待查显示未知而非 0。
- **配置和操作**：合约管理、参数单位及生效值、只观察/只平/允许开仓、按合约暂停、核对、预览纠正、恢复交易分开；改动先预览、留版本。明确提示“暂停不撤柜台挂单”；配置保存不自动开启实盘。

## 8. 交付顺序及放行标准

|阶段|交付/退出条件|
|---|---|
|A 基线|选取一笔真实争议交易，脱敏导出委托、成交、双腿持仓及本地日志。冻结参数版本，列出可证事实/未知项；保存旧账与配置副本。先停无人值守实盘，不自动撤已有委托|
|B 事实账本优先|实现标识、乱序事件归并、落盘、恢复、核对与唯一发单门禁；用假柜台验证，不依赖 Qt。先解决虚假全成、撤单超时释放、旧快照放行|
|C 策略与状态机|同一输入重放得同一信号、目标价、层账和发单意图；对拍旧策略公式，另列本次有意改变的换止盈顺序、行情清洗差异|
|D 工作台与影子运行|真实行情只读，不发送；界面从同一账本读。能从一行异常钻取到原始证据。回测检验信号，模拟/事件回放检验订单，不能用触价即成交回测代替执行验收|
|E 切换|推荐空仓、无活单窗口切换；有存量时逐笔验证归属并签认，否则仅观察。新旧引擎不同时发单。先模拟柜台，再经人授权单账户/单价差限额运行；账差或异常立即禁新单。回滚先隔离写入者、盘点柜台活单/持仓，不把旧数据库覆盖回去继续跑|

**发布阻断测试（每条不仅验最终净仓，还查中途实际发过几张单、每层归属及 UI 状态）：**

- [ ] 多空镜像、负/零价差、等于阈值不开、长短窗不同、预热不足、无效行情、四边费用/方向取整、平今平昨、关闭止损不误触发。
- [ ] 三层完整往返 0→1→2→3→2→1→0；满层含未决开仓不超量；始终至多一张可能仍在柜台的策略止盈单，且其量不超过关联层可平量。
- [ ] 加仓未成、部分成、拒单；旧止盈先成、新开先成、两者同到、撤回报超时：同一事件排列不得产生重复开平，切换期不可继续加仓。
- [ ] 2 组委托只成 1 组，两条各 1 手派生腿仍是 1 组；重复成交/先委托后成交/先成交后委托/撤余后迟到成交，均只入账一次。柜台报全成、明细未齐不得补发。
- [ ] 刚确认空仓后，其他终端成交；查询部分返回/超时、委托不可解析、资金过期、陈旧磁盘活单覆盖新终态、日切/换账户：按影响范围冻结，未知不显示为无仓无单。
- [ ] 单腿不配对、共用腿、锁仓、手工仓、合法零成本价差；归属不明不能自动接管。全部腿数量相同但逐层成本不同，收益仍按真实成交算。
- [ ] 意图落盘前后、已发未回、撤请未回、成交写入中断时重启；连续重放两次仍得相同账本，无重复报单。GUI/CLI/定时并发启动只有一个实盘写入者。
- [ ] 正常暂停再恢复，能够认回本策略原建层；暂停期间成交照记；迟到消息不会复活终态。每一笔实际单都有理由、每项差异都有处置状态。

**首版建议锁定的决策**：原生组合单、单账户单写、每次报单核查、只挂顶层、加仓成交后换单。实施前需按所用期货公司模拟柜台验证：组合成交的实际回报形态、可查询历史范围、报撤限频、自成交限制、跨会话标识和手续费。若柜台能力不满足验证要求，该品种维持只观察。另需业务签认：部分成交余量处置、多手层盈利目标分摊、缺口层序重排、超时告警时限；不应在编码时默作决定。
